## Correcting the earlier invented `struct x,y` C++ type

Previously the maintained
[`NativeGlyphMaskOffsets.hpp`](../src/NativeGlyphMaskOffsets.hpp)
declared an artificial pair `struct GlyphMaskOffset { int x,y; }`.
Although its 8B memory layout and generated PMR-vector helper code
were physically compatible with the original, direct `.x` / `.y`
loads **silently removed all four original offset-index E8 calls**
from the enclosing 2,245B game Boss. Read-only original Ghidra
and native x86 independently show two actual indexed calls each
time a reflected offset is loaded from the vector iterator. The
maintained source now uses **`GlyphMaskOffset =
std::array<std::int32_t,2>`**, retains the same **8B element /16B
PMR vector i386 ABI**, and loads the two live signed coordinates
through `.operator[](0)` and `.operator[](1)` **once each** before
evaluating the original four stencil neighbors. It does not perform
four index calls per neighbor or invent a memory copy.

Pinned MSVC 19.44 i386 C++20
`/Od /Ob0 /GS /Gy /Zl /arch:SSE2 /fp:precise /sdl /EHsc`
now naturally emits a complete **22B**
`std::array<int32_t,2>::operator[](size_t) const` method that is
**22/22 structurally identical to the preexisting native folded
`0x00414580` code**, as verified by actual original bytes. The
recompiled original-related game Boss naturally emits **four
separate REL32 E8 fields** to this true C++ array method: compiler
field offsets `+0x28F`, `+0x2A1`, `+0x649`, `+0x65B`; their native
unrelocated equivalents are anchored by the original genuine four
physical E8 sites above. There is no synthesized `Vector3` class
or fake target implementation. Identical original x86 does not by
itself prove the historical C++ source's exact type spelling, but
the typed `std::array<int32_t,2>` source now expresses the observed
native **indexing behavior, size, physical call roles and PMR
container layout** faithfully.
