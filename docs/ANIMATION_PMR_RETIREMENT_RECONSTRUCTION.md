## Independent native lifetime and SDK evidence

The previously accepted real File destructor invokes clear, then destroys stem
and filename in reverse member order. Its existing 29-byte PMR string destructor
calls the 139-byte tidy routine and the 23-byte compressed-pair destructor.
These complete native callers establish the chain independently of the new
comparison fields. The automatic ATL label on `004491C0` does not establish its
source identity. The actual PMR member call and nested string-value destruction
corroborate the maintained SDK instantiation instead.

The string value begins four bytes after the allocator-bearing pair. Within
that value, native size and capacity are at +10 and +14; capacity greater than
15 selects external storage. Tidy first calls container orphaning, conditionally
releases the external pointer and switches the union to its inline buffer, then
writes size zero, capacity 15 and a terminating character. The capacity helper
passes capacity plus one to the actual allocator. No capacity check or overflow
policy is added to the observed expression.

The character allocator retains its resource pointer, passes the original
pointer and byte count with alignment one, and invokes the 45-byte resource
method. That method dispatches through vtable slot +08 with thiscall and three
stack arguments, returning with RET 0C. This is the SDK resource contract;
loaded File buffers and texture ownership are separate game protocols.

The pinned MSVC SDK's xstring, xmemory and xpolymorphic_allocator.h corroborate
these class members, capacity threshold, destruction order and resource argument
flow. Under the actual configuration, destructor tombstones are disabled. The
compressed-pair and string-value destructors are implicit compiler-generated
bodies; the seven other classified routines have explicit library definitions.
The installed compiler is 19.44.35211; agreement under this recipe does not
establish the original global SDK, compiler flags or translation-unit partition.

Switching the union first destroys the pointer member, then retains the
constant-evaluation-only sixteen-byte zeroing loop. Narrow-character assignment
also retains its constant-evaluation branch to generic character assignment.
The complete native predicate returns false in AL. Ordinary SDK code emits this
behavior; no maintained fake return or manually removed branch is introduced.
